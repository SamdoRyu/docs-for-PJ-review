`doc-consistency-auditor` 서브에이전트에게 문서 정합성 감사를 위임한다.

감사 범위: $ARGUMENTS (비어 있으면 docs/00~07 전체)

## 위임할 때 전달할 것

1. 감사 범위. `최근` 이면 먼저 `git log --oneline -10 -- docs/` 로 최근 건드린 문서를 확인해 목록으로 넘긴다. `04 중심` 처럼 특정 문서를 지정받아도, **증거로 읽을 문서는 00~07 전부**라고 함께 전달한다.
2. 직전 회의에서 결정된 사항이 이 대화에 있으면 같이 넘긴다 — 후순위로 미룬 항목, 새로 추가된 요구, 번호를 재정렬했는지 여부. 서브에이전트는 이 대화를 보지 못한다.
3. 번호 재정렬이 있었다면 그 사실을 명시한다. C2(재정렬 잔존 참조) 검사의 우선순위가 올라간다.
4. C9(정의서·기획안 ID ↔ 이슈 ↔ docs 연결)를 함께 점검하라고 전달한다. 기준은 정의서 v0.1과 `docs/requirements-changes.md` 이고, 이슈는 `gh` 조회 명령으로만 읽는다. 새로 결정된 TBD나 채택·제외된 제안 ID가 이 대화에 있으면 같이 넘긴다.

## 리포트를 받은 뒤

- 리포트 전문을 `docs/reviews/consistency-YYYY-MM-DD.md` 로 저장한다. `docs/reviews/` 가 없으면 만든다.
- 대화에는 **판정 · BLOCKER 목록 · 확인 필요 항목**만 요약해 보여준다. 전문을 다시 펼치지 않는다.
- **리포트의 제안을 문서에 자동 반영하지 않는다.** 팀이 적용할 항목을 고른 뒤에만 문서를 수정한다. 수정은 `planning-partner` 의 일이다.
- `SELF-AUDIT: FAIL` 이면 그 사실을 먼저 알리고, 미완료된 검사만 다시 돌릴지 묻는다.

## 수정까지 진행하기로 결정된 경우

`.claude/rules/git-workflow.md` 를 따른다.

- 브랜치: `docs/<이슈번호>-<slug>`
- 커밋: `docs: <한 줄>`
- 한 브랜치에서 **한 문서만** 고친다. 여러 문서를 고쳐야 하면 이슈를 나눈다.
- 문서를 고치면 00-backlog.md의 「번호 매핑」·「참고 이력」도 같은 PR에서 갱신한다. 이걸 빼먹으면 다음 감사에서 C2가 판정 근거를 잃는다.
- PR 본문의 "주요 변경 사항"에 `consistency-YYYY-MM-DD.md 의 F-NN 을 닫았다` 를 한 줄 추가한다.
