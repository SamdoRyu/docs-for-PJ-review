```

├─ adapters/

│  ├─ fake/                시연 · 테스트용 가짜 데이터

└─ core/                   순수 규칙 — 막힘 계산 · 컨벤션 검사 · [제안] 투표 판정 · [제안] 카드 조립
```

## 모듈 경계 — api · adapters · store · packs · core

| 모듈 | 무엇 | 규칙 |
| --- | --- | --- |
| `core` | 순수 규칙. 계산 · 판정 | 외부 서비스 없이 단위 테스트할 수 있어야 한다. GitHub · DB · env 를 직접 부르지 않는다 |
| `adapters/github` | GitHub 원본(`Github*`)을 읽어 앱 모델(`Task` · `Submission` 등)로 바꾼다 | GitHub API 는 여기서만 부른다. POST · PATCH · PUT · DELETE 를 보내지 않는다(CON-02). GitHub 원본 모양을 밖으로 내보내지 않는다. 동기화 실패를 삼키지 않는다(FR-GH-05) |
| `adapters/fake` · `adapters/local` | 가짜 · 로컬 데이터 | 화면 시연과 테스트는 fake 로 한다. GitHub 없이도 사무실이 채워져야 한다 |
| `store` | 앱 모델 · 엔티티 저장 | GitHub 에서 온 값은 `syncedAt` 을 함께 저장한다. 시각은 UTC |
| `packs` | 용어 · 기능 묶음 · 기준값 기본값 | 막힘 12시간 · 24시간, 투표 3명 중 2표, PR 400줄 같은 기준값은 코드에 박지 않고 팩과 레포 설정에서 읽는다 |
| `api` | 요청 · 응답 DTO | 요청은 서버에서 다시 검증한다. 응답은 역할과 본인 여부에 따라 필드를 뺀다 — 개인 지표는 본인 요청에만(NFR-06), 사람별 합계 필드는 만들지 않는다(FR-FLOW-06 · FR-LRN-09). 에러는 `{ "code": "...", "message": "..." }` |

## GitHub 원본 상태와 앱 상태

두 종류의 상태를 섞지 않는다. 값 목록은 05-policy.md 「상태값」이 기준이다.

| 종류 | 예 | 누가 바꾸나 | 어디에 |
| --- | --- | --- | --- |
| GitHub 원본 상태 | 이슈 담당자 · 열림 · 닫힘, PR 열림 · 리뷰 요청 · 머지 · 닫힘 | GitHub(사람이 GitHub에서). 앱은 다음 동기화에 반영만 한다 | `adapters/github`가 읽어 앱 모델(`Task` · `Submission`)로 바꾸고 `syncedAt`과 함께 `store`에 둔다 |
| 계산한 값 | 사무실 위치(백로그 · 책상 · 검토 · 완료 선반, [제안] 머지 준비 선반), 막힘, 진행률, 팀 지표, 규칙 위반(06 「규칙 위반 (계산)」), [제안] PR 투표 상태(투표에서 계산 — 06) | `core`가 원본 상태와 앱 상태에서 계산한다. FR-HAB-11 새 위반 알림처럼 이전 값이 필요하면 저장 여부를 다시 정한다 | `core` |
| 앱 상태 | 요구사항–이슈 연결, 동기화 상태, 회의 안건 상태, [제안] PR 투표, [제안] 도움 요청 상태 | 앱 사용자 · 앱 규칙 | `store` (앱 서버에만 — CON-02) |

- PR이 회의 안건이 되어도 PR 투표 상태는 바뀌지 않는다. 안건은 따로 저장한다(06-data.md 「PR 투표 상태」).
- 원본 상태를 앱이 바꾸는 경로는 없다. 머지 · 이슈 만들기는 GitHub 화면 링크로 넘긴다(P3).

### 도형 5종

## 인증

GitHub 로그인과 레포 읽기는 **GitHub App 하나**로 처리한다. OAuth App은 비공개 레포를 읽으려면 쓰기까지 포함된 `repo` 권한이 필요해서 읽기 전용 최소 권한(NFR-04)을 지킬 수 없기 때문이다 — 개발 컨벤션 > 환경 변수 가이드.

- GitHub App 권한은 Metadata, Contents, Issues, Pull requests를 모두 **읽기 전용**으로 둔다.
- 두 가지 자격 증명의 책임을 나눈다(환경 변수 가이드 「Key 리스트」).
  - **사용자 로그인** — `GITHUB_APP_CLIENT_ID` · `GITHUB_APP_CLIENT_SECRET`으로 GitHub 로그인을 처리해 "누가 들어왔는지"를 정한다. 앱 세션은 `SESSION_SECRET`으로 서명한다.
  - **레포 읽기** — `GITHUB_APP_ID`와 키 파일(`GITHUB_APP_PRIVATE_KEY_PATH`)로 설치 토큰을 받아 레포를 동기화한다. 이 토큰은 `adapters/github` 안에서만 쓰고 브라우저로 내보내지 않는다(NFR-04).
- 역할은 팀 레포의 GitHub 권한에서 정해진다 — write = 참여자(ROLE-01), admin = 레포 관리자(ROLE-02), `MASTER_ADMIN_GITHUB_LOGIN` = 전체 관리자(ROLE-03) · P1. 레포 권한을 어느 자격 증명으로 조회하는지, GitHub에서 권한이 바뀌거나 빠졌을 때 언제 역할을 다시 확인하는지는 기준 문서에 없다 — TODO(스택 확인 후 BACKEND_ASSIGNMENTS.md B1에서 정하고 05-policy.md P1에 반영).
- 레포 등록은 우리 조 조직 안의 레포만 받는다(ASM-02 · P2). 앱이 설치되지 않은 조직은 "승인 요청하기"로 GitHub 요청 화면에 넘긴다.
- **역할은 API에서 요청마다 확인한다**(FR-AUTH-04). 화면에서 버튼을 숨긴 것을 권한 확인으로 보지 않는다. 클라이언트가 보낸 사용자 값을 믿지 않는다.
- 토큰 · 쿠키 · 이메일을 로그에 남기지 않는다. 디버깅이 필요하면 앞 4자리만 남기고 가린다(NFR-04).
- 키 파일(`*.pem`)은 `./secrets/` 에만 둔다.
