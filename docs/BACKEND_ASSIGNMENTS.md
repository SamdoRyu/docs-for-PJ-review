## 이 표를 믿는 범위

> **이 문서는 snapshot / cross-check 전용이다.** 착수 가능 여부는 이 표가 아니라 아래 순서로만 판정한다.
>
> 1. 배정 Issue **본문의 상태**와 "요구사항 ID" 칸
> 2. 「선행」의 Issue 마다, 그 PR 이 `origin/main` 에 squash merge 됐는지
> 3. 필요한 TBD 가 05-policy.md 서비스 정책에서 [?] 가 아닌지

- 1~3 을 모두 통과했는데 이 표가 막혀 있으면 작업을 막지 않고 "BACKEND_ASSIGNMENTS 가 GitHub Issue 와 불일치 — 문서 stale" 만 보고한다.
- 반대로 Issue 본문이 막혀 있으면 이 표가 열려 있어도 막힌 것이다.
- 선행은 Issue 가 open/closed 인지로 판단하지 않는다. PR 에 `Closes #N` 을 빠뜨리면 머지된 작업의 이슈가 open 으로 남을 수 있다.
- 브랜치 이름은 번호에서 추론하지 말고 Issue 에 적힌 값을 쓴다(`<type>/<이슈번호>-<slug>`).

## 공통 계약 소유와 변경 권한

여러 Claude Code 세션이 병렬로 구현하므로 **공통 계약은 먼저 정하고, 바꿀 때는 따로 낸다**(2026-11-01 결정). 계약 목록 · 초안 · 변경 절차는 [CONTRACTS.md](./CONTRACTS.md) 「9. 계약 변경 절차」가 기준이다.

| 계약 | 소유 | 함께 확인 | 1차 단계에서 확정할 것 |
| --- | --- | --- | --- |
| 도메인 모델 · JPA Entity 관계 · DB 스키마(migration) | B · C 공동 | D | 사무실(Workspace) 소속, 평가 회차, 안건 원본 참조, 마감 |
| 요청 · 응답 DTO · API 경로 | B · C 공동 | D | CONTRACTS.md 「4」 · 「5」 |
| 공통 에러 응답 · Spring Security 설정 · 인가 서비스 | B | C | 역할 판정 · 사무실 접근 · CSRF · 세션 |
| GitHub 어댑터 인터페이스 · Seed 어댑터 | B | C | 읽기 메서드 목록 |
| 브라우저 `DataSource` · 화면 타입 | D | B · C | API 묶음과 1:1 대응 |
| SceneModel · ThemeLayout | D | — | 공간 역할 · 드롭 결과 |

- 계약 파일은 **기능 PR에서 고치지 않는다.** 계약 PR을 따로 내고 소유 · 확인 역할이 모두 리뷰한 뒤 머지한다.
- 공통 파일(Spring 설정 파일, 공통 `common/` 패키지, 빌드 설정, `package.json`)도 같은 방식이다.
- 다른 패키지의 Repository를 직접 부르지 않고 그 패키지의 Service를 부른다 `[제안]` — 패키지 경계에서 충돌이 줄어든다.
