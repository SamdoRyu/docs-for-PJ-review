## PR 평가 결정 (2026-10-29)

PR 찬성 · 반대 투표는 머지의 계기가 아니라 **평가 척도**다. 이름과 규칙을 그에 맞게 바꾼다. 아래가 앞선 결정("투표로 머지 준비 상태가 된다", "그대로 머지면 머지 준비로", 투표 기준 3명 중 2표)보다 우선한다.

| # | 쟁점 | 결정 |
| --- | --- | --- |
| 1 | 이름 | 찬성 · 반대 → **추천 · 비추천**, 투표 → **평가**, 재투표 → **재평가**. 코드 이름은 `Evaluation`(`recommend`, `not_recommend`) |
| 2 | 이유 | 추천 · 비추천 **모두 한 줄 이유 필수**. 이유 없는 평가는 저장되지 않는다 |
| 3 | 머지 준비 | **머지 준비 상태 · 선반을 없앤다(A안).** 평가 결과는 PR 상태나 위치를 바꾸지 않는다. PR 삼각기둥은 검토 영역에 있다가 GitHub에서 머지 · 닫히면 다음 동기화에 완료 선반으로 간다. 평가 기준값(3명 중 2표)도 없앤다 |
| 4 | 보이는 것 | 추천 · 비추천 수와 이유를 삼각기둥 위와 상세 패널에 보인다. 평가자는 보이지 않는다(TBD-13). 사람별 합계는 없다(FR-LRN-09) |
| 5 | 머지 | 앱에서는 머지할 수 없다. 모든 열린 PR에 GitHub PR 화면 링크가 있고, 머지는 GitHub에서 사람이 판단한다(머지 조건은 GitHub 리뷰 승인 1명 — Git 전략) |
| 6 | 회의실 안건 | 평가 결과와 상관없이 팀 판단으로 올린다. 추천이 많아도 더 배울 게 있으면 올리고, 비추천이 많아도 바로 정리되면 올리지 않는다(FR-LRN-04 그대로) |
| 7 | 그대로 두는 것 | 새 커밋이 오거나 회의에서 "수정 후 재평가"로 정하면 평가가 초기화된다(FR-LRN-06, Must). 평가자 익명(TBD-13), 사람별 합계 금지(FR-LRN-09) |

## 강사 역할 결정 (2026-10-30)

LMS 기능을 강화하려고 강사 역할(ROLE-04)을 v1에 더한다. 강사는 **모든 것을 보되, 학생이 도움을 요청한 곳에서만 돕는다.** 아래가 앞선 결정과 문서(정의서 v0.1 포함)보다 우선한다. 이번 결정으로 생긴 요구사항은 모두 **채택 · Must**다.

### 1. 범위와 원칙

| # | 쟁점 | 결정 |
| --- | --- | --- |
| 1 | 강사 기능의 v1 범위 | v1에 넣는다. "강사·운영진 전용 기능 제외"에서 강사를 뺀다 — 제외 문구는 "운영진 전용 기능"으로 줄인다. 출석 · 공지 · 자료실은 계속 제외한다 |
| 2 | 컨벤션 라이브러리 | 출석 · 공지 · 자료실과 다른 기능이다. 강사가 컨벤션 형식을 올려 두는 참고용 라이브러리다 |
| 3 | 판정 원칙 (SP3) | 유지한다. 판정은 팀원끼리 한다. 강사는 도움을 요청한 학생에 한해 강사의 시각에서 도움(답변 · 꼬리질문 · 결정 피드백)을 주고, 결정 · 평가 · 안건 · 도움 요청의 상태를 바꾸지 않는다 |
| 4 | 대상 범위 (ASM-02) | 바꾼다. GitHub 조직이 가장 큰 단위이고 조마다 별도 조직이다. 앱은 조마다 조직에 설치한다. 학생(참여자 · 레포 관리자)은 자기 조 조직의 레포만 보고, 강사는 콜라보레이터로 추가된 모든 조의 레포를 본다(2026-10-30 결정 — 정의서 ASM-02와 다름) |
| 5 | 팀 간 비교 | 강사에게도 금지다. 조 간 비교 화면 · 수치는 없다 |
| 6 | 강사와 팀원 수 | 강사는 팀원이 아니다. 책상 · 아바타가 없고, 스탠드업 참석자 · 평가 인원 · 담당 뷰 · 팀 지표에 들지 않는다 |
| 7 | 습관 체크 | **기능을 통째로 없앤다.** 정의서 FR-HAB-01\~07은 삭제, 제안 FR-HAB-08\~11은 제외. 따라서 F7 · P10 · `ConventionRule` · 규칙 위반(계산) · 습관 체크 화면 · 팀 설정의 PR 크기 기준(400줄) · 게시판의 팀 규칙 표시 · `area:habit` 라벨 · IB-34\~39도 없앤다. 라이브러리는 습관 체크와 연결하지 않는다 |

### 2. 역할 판정

| # | 쟁점 | 결정 |
| --- | --- | --- |
| 1 | 역할 규칙 (P1) | "write 권한 = 참여자" 규칙을 없앤다. 팀 레포 **admin = 레포 관리자(ROLE-02)**, 레포 관리자가 앱에서 강사로 지정한 사람 = **강사(ROLE-04)**, 그 밖의 레포 콜라보레이터 전원(read 포함) = **참여자(ROLE-01)**. 전체 관리자(ROLE-03)는 서버 설정 그대로 |
| 2 | 강사가 되는 절차 | 팀이 강사를 GitHub 레포 콜라보레이터로 추가하고, 레포 관리자가 앱 팀 설정에서 참여자 목록 중 그 사람을 강사로 지정한다 |
| 3 | 지정이 반영되는 때 | 바로 반영한다. GitHub 권한은 로그인할 때 확인해 세션에 두는 그대로이고, 강사 지정 여부는 요청마다 앱 DB에서 확인한다 |
| 4 | 강사 쓰기 거부 | 요청되지 않은 건에 쓰거나 허용되지 않은 쓰기를 하면 기존 code `forbidden_role`로 거부한다. 새 에러 code는 만들지 않는다 |

### 3. 보기와 쓰기

| # | 쟁점 | 결정 |
| --- | --- | --- |
| 1 | 보기 | 강사는 개인 지표(학습 타임라인 · 회고 리포트 · 기술 결정 카드)까지 전부 본다. "본인만 본다"던 규칙(NFR-06 · P5 · FR-LRN-08 · FR-REP-06 · 10)은 "본인과 강사만 본다"로 바뀐다. 다른 팀원은 여전히 못 본다 |
| 2 | 쓰기 | 기본은 보기 전용. 학생이 요청한 건에 한해 그곳에서만 쓰기(도움 요청 답변 · 꼬리질문 · 결정 피드백)가 열린다. 컨벤션 라이브러리 등록 · 편집은 언제든 할 수 있다 |
| 3 | 강사가 못 하는 것 | PR 평가, 안건 올리기 · 거두기, 회의 결정 기록, 요구사항 연결, 팀 설정, 활동 기록 확인 · 작성, 한 줄 동료 피드백 |
| 4 | 기술 결정 카드 | 강사는 모든 카드를 보지만 꼬리질문은 학생이 요청한 카드에만 쓴다. 꼬리질문은 강사가 직접 쓰고 AI로 만들지 않는다. 카드 9칸이 아니라 따로 붙는 영역에 둔다. TBD-11("동료는 내 카드에 의견을 남길 수 없다")은 동료에게만 해당하고 그대로다. FR-REP-08(질문 틀 자동 생성) · FR-REP-09(답 쓰기)는 후순위 그대로 |
| 5 | 도움 요청 | 강사는 모든 도움 요청을 보지만, 답은 요청자가 "강사에게 요청"을 켠 글에만 단다. 강사 답변은 "도움이 된 코멘트"로 고를 수 없다. 강사가 답해도 상태는 바뀌지 않는다(해결은 요청자가 닫을 때만 — FR-LRN-17, 48시간 안건 후보 — FR-LRN-18 그대로). 안건으로 전환하면 강사 답변도 코멘트 기록과 함께 붙는다(FR-LRN-19) |
| 6 | 회의 결정 피드백 | 팀원 누구나 결정 기록에 강사 피드백을 요청한다. 피드백은 결정 기록 아래 팀 전체에게 보이고, 안건을 올린 사람의 학습 타임라인과 회고 리포트에 들어간다. 결정 · 안건 상태는 바뀌지 않는다 |
| 7 | 컨벤션 라이브러리 | 형식은 컨벤션 5종(브랜치 이름 · 커밋 메시지 · PR 제목 · PR 본문 · 이슈 본문)과 이슈 · PR 템플릿. 강사 라이브러리 하나를 모든 조가 같이 보고(서버 전체에 하나 — 사무실 단위가 아님), 학생은 읽기만 한다 |
| 8 | 강사 화면 | 강사 요청함 화면을 새로 둔다 — 도움 요청 · 결정 피드백 · 꼬리질문 요청을 모아 보고 바로 답한다. 컨벤션 라이브러리 화면을 새로 둔다(강사 편집, 학생 읽기). 그 밖의 화면은 강사에게 보기 전용으로 열린다 |
| 9 | 우선순위 | 강사 요구사항은 모두 Must. 꼬리질문의 바탕인 FR-REP-07(기술 결정 카드)도 Should에서 Must로 올린다 |
