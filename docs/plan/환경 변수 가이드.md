# 환경 변수 가이드

## 원칙

레포에는 변수 이름과 설명만 담은 `.env.example`을 커밋하고, 실제 값은 팀이 정한 비밀 공유 수단으로만 주고받습니다. 이 페이지에도 값은 적지 않습니다.

- 실제 값 파일(`.env`, `.env.local`)과 GitHub App 키 파일(`*.pem`)은 `.gitignore`에 넣습니다.
- 값을 이슈, PR, 댓글, 채팅, 터미널 출력에 붙이지 않습니다. 확인은 "설정됨 / 미설정"까지만 합니다.
- 빈 값(`KEY=`)은 미설정과 같습니다. 서버는 시작할 때 필수 값을 검사하고, 없으면 바로 멈춥니다.
- 브라우저로 나가는 변수에는 비밀 값을 넣지 않습니다.
- Claude Code는 `.env` 계열 파일을 읽지 못하게 막아 둡니다 (`.claude/settings.json`의 `deny`).
- 막힘 기준 시간처럼 팀이 화면에서 조정하는 값은 환경 변수가 아니라 팩과 레포 설정에 둡니다.

## Key 리스트

GitHub 로그인과 레포 읽기는 GitHub App 하나로 처리합니다. OAuth App은 비공개 레포를 읽으려면 쓰기까지 포함된 `repo` 권한이 필요해서, 읽기 전용 최소 권한(NFR-04)을 지킬 수 없기 때문입니다.

| 변수 | 어디에 쓰나 | 필수 | 서버 전용 | 로컬 개발 값 | 관련 |
| --- | --- | --- | --- | --- | --- |
| `APP_ORIGIN` | 로그인 콜백 주소, 요청 출처 검사 | 필수 | 아니오 | `http://localhost:3000` (포트는 스택 확인 후) | FR-AUTH-01, NFR-05 |
| `SESSION_SECRET` | 로그인 세션 서명 | 필수 | 예 | 각자 만든 32자 이상 임의 문자열 | FR-AUTH-01 |
| `GITHUB_APP_ID` | 레포 읽기용 설치 토큰 발급 | 필수 | 예 | 개발용 GitHub App의 ID | FR-GH-01 |
| `GITHUB_APP_CLIENT_ID` | GitHub 로그인 | 필수 | 아니오 | 개발용 GitHub App 값 | FR-AUTH-01 |
| `GITHUB_APP_CLIENT_SECRET` | GitHub 로그인 | 필수 | 예 | 개발용 GitHub App 값 | NFR-04 |
| `GITHUB_APP_PRIVATE_KEY_PATH` | 설치 토큰 발급용 키 파일 경로 | 필수 | 예 | `./secrets/github-app.pem` | NFR-04 |
| `MASTER_ADMIN_GITHUB_LOGIN` | 전체 관리자 계정 지정 | 필수 | 예 | 본인 GitHub 아이디 | FR-AUTH-03 |
| `DATA_SOURCE` | 데이터 어댑터 선택: `github`, `fake`, `local` | 필수 | 예 | `fake` | NFR-08 |
| `PACK` | 용어·기능 묶음 선택 | 선택 | 예 | `bootcamp` | NFR-08 |
| `SYNC_INTERVAL_MINUTES` | GitHub 폴링 간격 | 선택 | 예 | `5` | FR-GH-03, TBD-06 |
| `DATABASE_URL` | 앱 서버 저장소 | 필수 | 예 | 로컬 DB 주소 (형식은 스택 확인 후) | 정의서 6장 |
| `LOG_LEVEL` | 로그 수준 | 선택 | 예 | `debug` |  |

## 환경별 설정

화면 작업은 `DATA_SOURCE=fake`로 GitHub 없이 하고, 연동 작업과 시범 운영만 실제 GitHub App을 씁니다.

| 환경 | `DATA_SOURCE` | GitHub App | 값을 가진 사람 |
| --- | --- | --- | --- |
| 로컬 화면 작업 | `fake` | 개발용 (로그인에만 씀) | 각자 |
| 로컬 연동 작업 | `github` | 개발용, 우리 조 레포에 설치 | 각자 |
| 시범 서버 (TBD-09) | `github` | 운영용 따로 생성 | 서버에만 |
| CI | 없음 | 없음 | env 없이 통과해야 함 |

**로컬 처음 설정**

1. `.env.example`을 복사해 값 파일을 만듭니다. 파일 이름(`.env` 또는 `.env.local`)은 스택 확인 후 정합니다.
2. 연동 백엔드 담당(B)이 개발용 GitHub App을 하나 만들어 둡니다. 권한은 Metadata, Contents, Issues, Pull requests를 모두 읽기 전용으로 두고, 콜백 주소는 `APP_ORIGIN` 기준으로 등록합니다.
3. B가 App ID, Client ID, Client secret, 키 파일을 팀 비밀 공유 수단으로 나눠 줍니다. 키 파일은 `./secrets/`에 두며, 이 폴더는 git과 Claude Code 양쪽에서 막혀 있습니다.
4. `MASTER_ADMIN_GITHUB_LOGIN`에 본인 GitHub 아이디를 넣고 서버를 띄웁니다.
5. 연동 작업을 할 때만 `DATA_SOURCE`를 `github`로 바꿉니다.

개발용 App을 모두가 함께 쓰려면 로컬 포트가 같아야 합니다. 포트가 다르면 콜백 주소가 어긋나 로그인이 실패합니다.

## .env.example

```bash
# 팀 오피스 v1. 값은 팀 비밀 공유 수단으로 받고, 이 파일에는 넣지 않는다.

# 앱
APP_ORIGIN=http://localhost:3000
SESSION_SECRET=
LOG_LEVEL=debug

# GitHub App (읽기 전용 권한)
GITHUB_APP_ID=
GITHUB_APP_CLIENT_ID=
GITHUB_APP_CLIENT_SECRET=
GITHUB_APP_PRIVATE_KEY_PATH=./secrets/github-app.pem

# 역할
MASTER_ADMIN_GITHUB_LOGIN=

# 데이터
DATA_SOURCE=fake
PACK=bootcamp
SYNC_INTERVAL_MINUTES=5
DATABASE_URL=
```

`APP_ORIGIN`, `DATA_SOURCE`처럼 비밀이 아닌 기본값만 채워 두고, 비밀 값은 비워 둡니다.
