# 환경 변수 가이드

> 2026-11-01 결정 반영: 백엔드는 Spring Boot(Spring Security 세션 · Spring Data JPA)로 새로 만들고, 외부 인터넷에서 접근하는 웹 애플리케이션으로 배포한다. 아래 「1」은 데모(Hono) 설정이라 **참고용**이다. Spring에서 변수를 어떻게 읽을지(`application` 설정 파일 · 환경 변수 매핑)와 DB 접속 변수 이름은 빌드 도구 · DB가 정해지면 정한다 — 결정 필요.

## 원칙

레포에는 변수 이름과 설명만 담은 `.env.example`을 커밋하고, 실제 값은 팀이 정한 비밀 공유 수단으로만 주고받습니다. 이 페이지에도 값은 적지 않습니다.

- 실제 값 파일(`.env`, `.env.local`)과 GitHub App 키 파일(`*.pem`)은 `.gitignore`에 넣습니다. **데모 저장소(`warehouseDemo_fork`)의 `.gitignore`에는 `*.local`만 있고 `.env`, `*.pem`, `secrets/`가 없습니다** — 개발 저장소에서 GitHub App 값을 받기 전에 먼저 추가합니다.
- 값을 이슈, PR, 댓글, 채팅, 터미널 출력에 붙이지 않습니다. 확인은 "설정됨 / 미설정"까지만 합니다.
- 빈 값(`KEY=`)은 미설정과 같습니다. 서버는 시작할 때 필수 값을 검사하고, 없으면 바로 멈춥니다(신규 예정 — 지금 서버에는 필수 값이 없습니다).
- 브라우저로 나가는 변수에는 비밀 값을 넣지 않습니다. 지금 화면 코드는 환경 변수(`import.meta.env`)를 하나도 쓰지 않습니다.
- Claude Code는 `.env` 계열 파일을 읽지 못하게 막아 둡니다 (`.claude/settings.json`의 `deny`).
- 막힘 기준 시간 · 강사 지정처럼 팀이 화면에서 조정하는 값은 환경 변수가 아니라 팀 설정(`TeamSettings`)에 둡니다(강사 지정 — 2026-10-30 결정).

## 1. 현재 데모에서 쓰는 설정 (참고)

데모 소스에서 확인한 것입니다(2026-10-28, 코드를 읽어서 확인). 모두 비밀 값이 아닙니다. `PORT` · `DEMO` · DB 파일은 데모의 Hono 서버 설정이라 v1 Spring 서버에는 그대로 쓰지 않습니다. 화면 쪽(`API_PORT` · `?source=api` · localStorage · E2E 포트)은 프론트를 재사용하므로 이어집니다.

| 설정 | 어디서 읽나 | 기본값 | 뜻 |
| --- | --- | --- | --- |
| `PORT` | `server/src/index.ts` | `8787` | API 서버 포트. 서버는 `127.0.0.1`에만 바인딩합니다 |
| `API_PORT` | `vite.config.ts` | `8787` | Vite 개발 서버가 `/api`를 넘길 API 포트. `PORT`와 같게 둡니다 |
| `DEMO` | `server/src/index.ts` | 없음 | `1`이면 서버 데모 봇을 켭니다. `0`은 끄지 않습니다(저장된 설정을 따름) |
| Vite 개발 서버 포트 | 설정 없음 | `5173` | Vite 기본값. `vite.config.ts`에 `server.port`가 없습니다 |
| 데이터 소스 선택 | `src/App.tsx` — 주소의 `?source=api` | mock | `?source=api`면 서버 API, 없으면 브라우저 localStorage 데이터. 환경 변수가 아닙니다 |
| DB 파일 | `server/src/app.ts` | `server/data/office.db` | 경로를 바꾸는 환경 변수가 없습니다. `server/data/`는 gitignore됩니다 |
| 브라우저 저장 | localStorage `office-dashboard:v1` 등 | — | mock 데이터 · 데모 설정. 비밀 값 없음 |
| E2E 포트 | `tests/e2e/env.ts` · `playwright.config.ts` | 웹 `5180`, API `8790` (오프라인 테스트는 `5181` · `8791`) | 테스트가 직접 띄웁니다. 이 포트들이 비어 있어야 합니다 |

## 2. GitHub 연동을 위해 새로 도입할 변수

**아래 변수는 아직 어느 코드에서도 읽지 않습니다.** 서버 인증 · 동기화를 만들 때 함께 도입합니다(BACKEND_ASSIGNMENTS.md B1 · B2).

GitHub 로그인과 레포 읽기는 GitHub App 하나로 처리합니다. OAuth App은 비공개 레포를 읽으려면 쓰기까지 포함된 `repo` 권한이 필요해서, 읽기 전용 최소 권한(NFR-04)을 지킬 수 없기 때문입니다. 조마다 별도 GitHub 조직이므로 이 App을 조마다 조직에 설치합니다(2026-10-30 결정).

| 변수 | 어디에 쓰나 | 필수 | 서버 전용 | 로컬 개발 값 | 관련 |
| --- | --- | --- | --- | --- | --- |
| `APP_ORIGIN` | 브라우저가 앱을 여는 주소. 로그인 콜백 주소의 기준, 요청 출처(Origin) 검사 | 필수 | 아니오 | `http://localhost:5173` (권장안 — 아래 설명) | FR-AUTH-01, NFR-05 |
| `SESSION_SECRET` | 로그인 세션 서명 — Spring Security 서버 세션을 쓰면 필요 없을 수 있다(확인 필요) | 결정 필요 | 예 | 각자 만든 32자 이상 임의 문자열 | FR-AUTH-01 |
| `GITHUB_APP_ID` | 레포 읽기용 설치 토큰 발급 | 필수 | 예 | 개발용 GitHub App의 ID | FR-GH-01 |
| `GITHUB_APP_CLIENT_ID` | GitHub 로그인 | 필수 | 아니오 | 개발용 GitHub App 값 | FR-AUTH-01 |
| `GITHUB_APP_CLIENT_SECRET` | GitHub 로그인 | 필수 | 예 | 개발용 GitHub App 값 | NFR-04 |
| `GITHUB_APP_PRIVATE_KEY_PATH` | 설치 토큰 발급용 키 파일 경로 | 필수 | 예 | `./secrets/github-app.pem` | NFR-04 |
| `MASTER_ADMIN_GITHUB_LOGIN` | 전체 관리자 계정 지정 | 필수 | 예 | 본인 GitHub 아이디 | FR-AUTH-03 |
| (승인된 강사 계정 목록) | 강사로 지정할 수 있는 계정 — **승인 · 등록 방법이 환경 변수(대안 A)로 정해질 때만** 필요하다. 이름은 정하지 않았다 | 결정 필요 | 예 | — | FR-AUTH-06 · P1 (2026-11-01 결정 — ARCHITECTURE.md 「인증과 권한」 대안 표) |
| (DB 접속) | Spring 데이터 소스 URL · 사용자 · 비밀번호 | 필수 | 예 | — | DB 종류와 변수 이름은 결정 필요(PostgreSQL 우선 검토 — `[제안]`) |
| `SYNC_INTERVAL_MINUTES` | GitHub 폴링 간격 | 선택 | 예 | `5` | FR-GH-03, TBD-06 |
| `LOG_LEVEL` | 로그 수준 | 선택 | 예 | `debug` |  |

**`APP_ORIGIN`이 가리키는 것**

로컬 개발에서는 주소가 셋입니다. 섞지 않습니다.

| 주소 | 값 (로컬) | 무엇 |
| --- | --- | --- |
| 화면 출처 | `http://localhost:5173` | 브라우저가 여는 Vite 개발 서버. 화면은 같은 출처의 `/api/*`를 부르고 Vite가 API로 넘깁니다 |
| 로그인 콜백 | 화면 출처 + 콜백 경로(경로는 신규 예정 — Spring Security 기본 경로를 쓸지 결정 필요) | GitHub가 로그인 뒤 브라우저를 돌려보내는 주소. 프록시를 거쳐 Spring 서버에 닿습니다. GitHub App 설정에 이 주소를 등록합니다 |
| API 서버 | Spring 서버 (로컬 주소 · 포트는 결정 필요) | 브라우저가 직접 부르지 않습니다(프록시 뒤) |

그래서 로컬의 `APP_ORIGIN`은 화면 출처(`http://localhost:5173`)로 두는 것을 권장합니다. 이전 초안의 `http://localhost:3000`은 스택 확인 전 값이라 쓰지 않습니다. 콜백을 프록시 경유로 받을지, API 서버가 직접 받을지는 인증 구현 때 정합니다 — 결정 필요. 외부 배포에서는 `APP_ORIGIN`이 HTTPS 공개 주소가 됩니다(SP11 · 2026-11-01 결정).

## 3. 팀이 정해야 하는 설정

| 항목 | 지금 | 선택지 | 권장안 |
| --- | --- | --- | --- |
| `DATA_SOURCE`(`github` · `fake` · `local`) | 없음. 데이터 소스는 브라우저 주소의 `?source=api`로만 고릅니다 | ① 서버 동기화 원천을 고르는 서버 환경 변수로 도입 ② 도입하지 않고 사무실 종류(실제 · 시연)로 고름 | ②(`[제안]`). 2026-11-01 결정으로 시연용 다른 레포는 서버의 Seed 사무실(가짜 데이터)로 보여 주므로, 서버 전체 변수보다 사무실마다 원천을 고르는 편이 맞습니다. 화면 개발 · 테스트의 가짜 데이터는 계속 브라우저 mock입니다(2026-10-28 결정). `local`이 무엇인지 정의가 없어 함께 정합니다 |
| DB 접속 | 없음 (데모는 SQLite 파일 고정 경로) | Spring 데이터 소스 설정 이름을 그대로 쓸지, 팀 변수 이름을 둘지 | 결정 필요 — DB 종류(PostgreSQL 우선 검토)와 함께 정합니다. 데모의 SQLite 경로 변수 안은 쓰지 않습니다(2026-11-01 결정) |
| `PACK` | 없음 | v1은 `bootcamp` 하나라 변수 없이 시작할 수 있습니다 | 팩이 둘이 될 때 도입 |
| 공개 주소 · 허용 출처 | 데모는 `127.0.0.1` 고정, Origin 검사는 localhost만 | 외부 인터넷 배포(SP11 · 2026-11-01 결정 — TBD-09 "팀원 컴퓨터 한 대"를 대신함) | 배포 대상이 정해지면 HTTPS 공개 주소를 `APP_ORIGIN`으로 두고 허용 출처 · 쿠키 설정을 함께 정합니다 |
| 서버 포트 · `API_PORT` | 데모는 둘 다 기본 8787 | Spring 서버 포트에 맞춤 | 개발용 GitHub App을 함께 쓰려면 화면 포트(5173)를 모두 같게 둡니다 |
| 값 파일 이름 | 없음 | `.env` 또는 `.env.local` | Spring이 값을 어디서 읽을지 정할 때 함께 정합니다 |

## 환경별 설정

화면 작업은 GitHub 없이 하고, 연동 작업과 시범 운영만 실제 GitHub App을 씁니다.

| 환경 | 화면 데이터 | 서버 데이터 원천 | GitHub App | 값을 가진 사람 |
| --- | --- | --- | --- | --- |
| 로컬 화면 작업 | mock(`?source=` 없음 — 가짜 데이터는 브라우저 mock, 2026-10-28 결정) 또는 api | — | 필요 없음 (로그인 화면 작업 때만 개발용) | 각자 |
| 로컬 연동 작업 | api(`?source=api` — Spring 서버) | 실제 GitHub | 개발용, 우리 조 조직에 설치 | 각자 |
| 시범 서버 (외부 인터넷 배포 — SP11 · 2026-11-01 결정) | api | 우리 조 사무실은 실제 GitHub, 시연용 다른 레포는 Seed 사무실("시연 데이터" 표시) | 운영용 따로 생성, 조마다 조직에 설치 (2026-10-30 결정) | 서버에만 |
| CI | — | 없음 | 없음 | env 없이 통과해야 함. 데모 저장소에는 아직 CI가 없습니다 |

**로컬 처음 설정 (GitHub 연동을 만든 뒤)**

1. `.env.example`을 복사해 값 파일을 만듭니다. 파일 이름은 위 「3」에서 정합니다.
2. 연동 백엔드 담당(B)이 개발용 GitHub App을 하나 만들어 둡니다. 권한은 Metadata, Contents, Issues, Pull requests를 모두 읽기 전용으로 두고, 콜백 주소는 `APP_ORIGIN` 기준으로 등록합니다.
3. B가 App ID, Client ID, Client secret, 키 파일을 팀 비밀 공유 수단으로 나눠 줍니다. 키 파일은 `./secrets/`에 둡니다. 그 전에 개발 저장소의 `.gitignore`와 `.claude/settings.json`에서 이 폴더가 막혀 있는지 먼저 확인합니다(데모 저장소는 아직 막혀 있지 않음).
4. `MASTER_ADMIN_GITHUB_LOGIN`에 본인 GitHub 아이디를 넣고 서버를 띄웁니다.
5. 연동 작업을 할 때만 GitHub 데이터를 씁니다.

개발용 App을 모두가 함께 쓰려면 화면 포트가 같아야 합니다. 포트가 다르면 콜백 주소가 어긋나 로그인이 실패합니다.

## .env.example

**신규 예정 초안입니다. 아직 어느 저장소에도 없습니다.** 개발 저장소 루트에 만들고, 위 「3」의 결정에 따라 DB 접속 · 세션 · 강사 계정 줄을 고칩니다. 이 문서 작업에서는 파일을 만들지 않았습니다.

```bash
# 오피스 v1. 값은 팀 비밀 공유 수단으로 받고, 이 파일에는 넣지 않는다.

# 화면 개발 (비밀 아님) — Vite 프록시가 넘길 Spring 서버 포트
API_PORT=

# 앱
APP_ORIGIN=http://localhost:5173
# SESSION_SECRET=   # Spring 서버 세션이면 필요 없을 수 있다 — 확인 필요
LOG_LEVEL=debug

# DB — 종류 · 변수 이름은 결정 필요 (PostgreSQL 우선 검토)

# GitHub App (읽기 전용 권한)
GITHUB_APP_ID=
GITHUB_APP_CLIENT_ID=
GITHUB_APP_CLIENT_SECRET=
GITHUB_APP_PRIVATE_KEY_PATH=./secrets/github-app.pem

# 역할
MASTER_ADMIN_GITHUB_LOGIN=
# 승인된 강사 계정 — 승인 방법이 환경 변수로 정해질 때만 (결정 필요)

# 데이터 — 화면 개발의 가짜 데이터는 브라우저 mock(2026-10-28 결정),
# 시연용 다른 레포는 서버 Seed 사무실(2026-11-01 결정). DATA_SOURCE 도입 여부는 결정 필요.
SYNC_INTERVAL_MINUTES=5
```

`APP_ORIGIN`, 포트처럼 비밀이 아닌 기본값만 채워 두고, 비밀 값은 비워 둡니다.
