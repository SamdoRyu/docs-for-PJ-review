# 요구사항 변경안 — 정의서 v0.1 대비

기획안(오피스 v1 기획안)이 요구사항 정의서 v0.1에 더하거나 바꾼 것을 정의서 형식으로 모은 문서다. 정의서 PDF는 수정하지 않고, 팀이 채택하면 정의서 다음 버전과 변경 이력에 옮긴다.

- 출처: `docs/plan/` 의 기획안. 요구사항과 수용 기준 문장은 기획안 원문을 그대로 옮겼다. FR-LRN-01~09 · 14 · FR-REP-08 · TBD-13은 PR 평가 결정에 맞춰 용어와 문장을 고쳤다(2026-10-29 결정). 「1. 추가」의 「강사 대응」 표는 기획안이 아니라 결정 기록(`docs/reviews/decision-meeting-2026-10-28.md` 「강사 역할 결정 (2026-10-30)」 「4. 새 ID」)의 문장을 그대로 옮겼다.
- 상태: `검토 중` → 팀 결정 후 `채택` · `보류` · `제외`(수정안은 `철회`). 2026-10-28 결정 회의에서 FR-LRN-01\~14 · FR-HAB-08\~11 · FR-REP-07을 채택했다. FR-FLOW-07은 보류했다가 정보 뷰 결정으로 채택했고, 최근 변화 뷰는 FR-FLOW-08로 더했다(2026-10-29 결정). FR-ACT-01\~04는 보류했다가 추가 결정으로 채택했고, 도움 요청(추가 제안 후보 1\~6)은 FR-LRN-15\~20으로 옮겨 채택했다(2026-10-28 추가 결정). FR-REP-10은 FR-REP-07 채택에 따라 Must다. 2026-10-30 강사 역할 결정으로 ROLE-04 · FR-AUTH-06\~08 · FR-LRN-21\~23 · FR-REP-11 · FR-LIB-01 · 02를 채택했고(모두 Must), FR-REP-07을 Must로 올렸다. 같은 결정으로 습관 체크를 없애 FR-HAB-08\~11은 제외했다. 2026-11-01 결정(`docs/reviews/decision-meeting-2026-10-28.md` 「기술 스택 · 공간 모델 · 학습 흐름 결정」)으로 「2. 수정」의 CON-05 · 강사 지정 대상 · 객체 위치 규칙 · FR-REQ-02 · FR-OFF-03 · FR-LRN-06 · FR-LRN-15 · 테마 표현 행을 채택했다. 2026-11-01 추가 결정(같은 결정 기록 「추가 결정 (2026-11-01, v3 검토 뒤)」)으로 원본 없는 4건(FR-AUTH-02 · FR-GH-02 · FR-GH-04 · FR-MTG-02)의 팀 재정의를 채택했고, 「2. 수정」의 FR-AUTH-01(심사용 로그인) · 강사 판정 · FR-REQ-02 묶는 기준 · 다중 담당자와 작업 마감 권한 행, 「4. 범위」의 외부 조직 온보딩 제외 행을 채택했다. 새 요구사항 ID는 없다. 2026-11-03 공통 계약 확정 결정(같은 결정 기록 「공통 계약 확정 결정 (2026-11-03)」 — 사용자 선택 Q1~Q6: ID · 요구사항 재동기화 · Snapshot과 개인 API · API 상세 · 계약 테스트 · 모노레포)은 요구사항이 아니라 구현 계약이라 「1」 · 「2」의 요구사항 표를 바꾸지 않았고(CONTRACTS.md), 「3. 결정」의 TBD-11\~13만 이 결정으로 `채택`했다(각 행 상태 칸). 같은 날 「3. 결정」에 TBD-02를 기존 결정의 적용으로 정리했다. FR-REP-08 · 09와 「4. 범위」의 v2 변경안은 아직 `검토 중`이다. 2026-11-06 범위 결정(결정 기록 「범위 결정 (2026-11-06)」)으로 FR-ACT-04를 v1에서 보류했다. 2026-11-10에는 새 결정 없이 03-requirements.md의 요구 문장 일부를 구현(GRAVIT main `6a65d1f`)에 맞췄다 — 「7. 구현 정합화 기록 (2026-11-10)」. 이 문서의 원문 인용은 고치지 않고, 해당 행 상태 칸에 "현재 구현은 …"만 덧붙였다.
- 충돌하면 기획안 > 개발 컨벤션 > 정의서 순으로 따른다.
- **원본 확인 필요**: 정의서 v0.1 PDF가 레포에 없다. 들어오면 "수정"과 "범위" 절의 정의서 원문 칸을 채운다. 원문이 없는 ID 목록과 영향 범위는 03-requirements.md 「원본 확인 필요 요구사항」에 있다. 데모 개발 과정에 원본 정의서가 따로 없었을 가능성이 높아(2026-11-01 결정), Must 4건(FR-AUTH-02 · FR-GH-02 · FR-GH-04 · FR-MTG-02)은 원문을 복원하지 않고 「2. 수정」 아래 「원본 없는 ID — 팀 재정의」에서 새로 정의했고, 2026-11-01 추가 결정으로 **공식 요구사항으로 채택**했다. 원문이 발견된 것은 아니므로 출처는 계속 "팀 재정의"다.
- **[제안] 표기 (docs 공통 규칙)**: 이 문서에서 `검토 중`인 요구사항이나 「5. 추가 제안 후보」에 기대는 부분이 읽는 사람에게 보이게 `[제안]`을 붙인다. 행 · 항목 단위로 붙이면 되고, 확정 요구사항과 섞인 행은 제안 부분 앞에 한 번만 붙인다 — 확정 요구사항도 쓰는 항목(예: 회의 안건)에 통째로 붙이지는 않는다. 채택되면 태그만 지우면 되고, 개수 집계나 이력 기록은 따로 하지 않는다. `보류`된 요구사항에 기대는 부분은 태그를 `[보류]`로 바꾸고 지우지 않는다. 우선순위 열의 값은 "제안 우선순위"로 읽는다 — 채택 전에는 Must라도 확정 MVP 범위가 아니다.
- 「5. 추가 제안 후보」는 기획안에 동작이 서술되어 있지만 요구사항 ID가 없는 것이다. 1\~6(도움 요청)은 FR-LRN-15\~20으로 옮겼다(2026-10-28 추가 결정). 나머지는 팀이 ID를 줄지 정한다.
