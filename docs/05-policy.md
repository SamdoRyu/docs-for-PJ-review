## 상태값

- **사무실**: 열리지 않음 → 열림 · 전이 조건: 레포 관리자가 레포를 등록하고 팀 설정(기간, 명세 문서 경로)을 마치면 열림 · P2
- **동기화**: 정상 ↔ 실패 · 전이 조건: 폴링·수동 동기화가 실패하면 정상→실패(마지막 성공 시각과 사유를 남기고 화면은 마지막 데이터 유지), 다음 동기화가 성공하면 실패→정상 · P4
- **이슈 상자 위치**: 백로그 선반(담당자 없음) → 담당자 책상(담당자 지정) → 검토 영역 → 완료 선반(머지·닫힘) · 전이 조건: GitHub 데이터가 다음 동기화에 반영될 때. 앱에서는 위치를 바꾸지 않는다 · P3
- **PR**: 투표 중 → 머지 준비 → 완료 선반 · 전이 조건: 새 PR이 동기화되면 "투표 중", 기준값(찬성 2표·반대 0)을 채우면 "머지 준비", GitHub에서 머지·닫히면 다음 동기화에 완료 선반. "수정 후 재투표" 결정이나 새 커밋이 생기면 "투표 중"으로 돌아간다 · P7. 투표 결과와 상관없이 회의실로 올라가면 "회의 안건" 표시가 함께 붙는다 · P8
- **회의 안건**: 후보(반투명) → 확정(불투명) → 회의를 거친 항목(메모 표시) · 전이 조건: 앱이 찾은 후보를 버튼이나 드래그로 확정, 사람이 직접 만든 안건(배운 점 공유, 기타)은 바로 확정. 회의에서 결정과 배운 점을 기록하면 회의를 거친 항목. 회의 전에는 올린 사람이 거둘 수 있다 · P8
- **도움 요청**: 열림 → 논의 중 → 해결(닫힘) · 미해결 시 논의 중 → 안건 후보 → 안건 → 종료 · 전이 조건: 팀원이 코멘트하면 논의 중, 요청자가 닫으면 해결(도움이 된 코멘트와 배운 점 한 줄을 남김), 일정 시간 안에 해결되지 않으면 안건 후보(TODO: 시간 값), 확정되면 안건, 회의에서 해결되거나 이슈로 만들기로 결정하면 종료 · P8
- **규칙 위반**: 미해결 → 해결 · 전이 조건: 본인이 GitHub에서 고친 뒤 다음 동기화에서 확인되면 해결 · P10
- **기술 결정 카드**: 본인 확인 전 → 확인됨 · 전이 조건: 본인이 칸을 확인하고 "내가 배운 점"을 쓰면 확인됨 · P11
- **활동 기록**: 확인 대기 → 확인됨 · 전이 조건: 작성자 외 1명 이상이 확인하면 확인됨 · P12
