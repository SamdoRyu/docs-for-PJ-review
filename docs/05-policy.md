## 상태값

GitHub에서 읽은 원본 상태와 앱이 정하는 상태를 나눠 적는다. 원본 상태는 앱이 바꾸지 않고 다음 동기화에 반영만 한다(P3).

- **사무실**: 열리지 않음 → 열림 · 전이 조건: 레포 관리자가 레포를 등록하고 프로젝트 기간을 입력하면 열림. 명세 문서 경로는 건너뛸 수 있고(FR-REQ-01), [제안] 활동 기록 수집 동의는 FR-ACT 채택 시에만 열기 단계에 든다 · P2 · P12
- **동기화**: 정상 ↔ 실패 · 전이 조건: 폴링·수동 동기화가 실패하면 정상→실패(마지막 성공 시각과 사유를 남기고 화면은 마지막 데이터 유지), 다음 동기화가 성공하면 실패→정상 · P4
- **이슈 · PR 원본 상태 (GitHub)**: 이슈는 담당자 유무 · 열림 · 닫힘, PR은 열림 · 리뷰 요청 · 머지 · 닫힘 · 전이 조건: GitHub에서 바뀐 값이 다음 동기화에 반영될 때. 앱에서는 바꾸지 않는다 · P3
- **사무실 위치 (원본 상태 · [제안] PR 투표 상태에서 계산)**: 백로그 선반(담당자 없음) · 담당자 책상(담당자 지정) · 검토 영역(PR 열림 · 리뷰 요청) · [제안] 머지 준비 선반(PR 투표 상태 = 머지 준비) · 완료 선반(머지 · 닫힘) · P3
- **PR 투표 상태 [제안]**: 투표 중 → 머지 준비 · 전이 조건: 새 PR이 동기화되면 "투표 중", 기준값(찬성 2표 · 반대 0)을 채우면 "머지 준비". GitHub에서 머지 · 닫히면 투표는 끝나고 위치는 원본 상태를 따라 완료 선반. 재투표(FR-LRN-06, 제안 Should): "수정 후 재투표" 결정이나 새 커밋이 생기면 새 회차로 "투표 중"에 돌아간다. FR-LRN-06이 없을 때의 새 커밋 처리와, 회의 결정 "그대로 머지"와 반대표의 관계는 [?] · P7
- **회의 안건**: 확정 → 회의 완료(메모 표시, 기획안의 "회의를 거친 항목") · [제안] 후보(반투명) → 확정(불투명) · 전이 조건: 회의에서 결정과 배운 점을 기록하면 회의 완료(FR-MTG-03 · 04). [제안] 앱이 찾은 후보를 버튼이나 드래그로 확정, 사람이 직접 만든 안건(배운 점 공유, 기타)은 바로 확정. [제안] 확정 뒤 회의 전에는 올린 사람이 거둘 수 있다 — 거둔 안건 · 확정되지 않은 후보의 처리는 [?] · P8. PR이 회의 안건이 되어도 PR 투표 상태는 바뀌지 않는다 — 안건은 PR 투표 상태와 따로 붙는 별도 항목이다(FR-LRN-04 "투표 결과와 상관없이")
